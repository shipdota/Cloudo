## 2024-06-15 - Missing TTL Caching on Read-Heavy Routes
**Learning:** The application performs heavy database queries (e.g. `/leaderboard` selecting, joining, and sorting top scores) on every request without caching. Implementing an in-memory TTL cache using standard Python library tools (`time`, `threading.Lock`) can significantly reduce latency and database load. However, to prevent "cache stampedes" upon expiration, a double-checked locking pattern is necessary to ensure only one thread performs the expensive update while others wait, without penalizing the fast path. Also, to minimize lock duration, expensive operations like `render_template` must remain outside the lock block.
**Action:** Apply the double-checked locking pattern for in-memory TTL caching on read-heavy global endpoints, ensuring thread safety and minimal lock contention, while avoiding unapproved third-party dependencies.
