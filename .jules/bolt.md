## 2024-05-24 - Double-Checked Locking in Flask Caching
**Learning:** When implementing in-memory TTL caches in Flask apps using `threading.Lock`, using the double-checked locking pattern is crucial to prevent cache stampedes upon expiration. Furthermore, to avoid lock contention, the lock duration should be kept minimal by only performing the dictionary updates inside the lock and pulling expensive operations like `render_template` outside. Returning directly from a `with lock` block is an anti-pattern as Python evaluates the return expression before releasing the lock, keeping the thread blocked unnecessarily.
**Action:** Always implement double-checked locking with a recalculated timestamp inside the lock, minimize the lock block scope, and assign the cached value to a local variable before releasing the lock and returning it. Ensure error handling falls back to a safe default like an empty list if the cache was never successfully populated.
