## 2024-05-24 - Double-Checked Locking in Flask Caches
**Learning:** When implementing in-memory TTL caches in a multi-threaded web server like Flask, a simple lock around the update logic isn't enough; concurrent requests might wait on the lock and then all unnecessarily fetch from the database when it's released (a cache stampede). Checking cache validity outside the lock (fast path) and then re-checking inside the lock (slow path) prevents this, but only if the time is recalculated inside the lock to avoid using a stale timestamp.
**Action:** Always use the double-checked locking pattern for TTL caches and ensure `time.time()` (or equivalent) is re-evaluated within the locked block. Also, safely fallback to existing cached data (or an empty list `[]`) to prevent template errors if the initial fetch fails.
