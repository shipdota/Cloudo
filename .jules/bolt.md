## 2024-05-24 - Supabase Query Bottleneck in Global Leaderboard
**Learning:** Frequent queries to Supabase for the global leaderboard were becoming a bottleneck, as it fetched top scores synchronously on every request to `/leaderboard`. We solved this by implementing a `time` and `threading.Lock` based TTL cache (60 seconds TTL) within the application's global state so we avoid unnecessary continuous network calls for slowly-changing shared data. Also learned that when using global variables for caching in pytest tests across Flask app instances, we must reset the global module variables directly (e.g. `import app.main as app_main; app_main.leaderboard_cache = None`) to maintain test isolation.
**Action:** For all globally shared, read-heavy, and slowly-changing data fetched from Supabase, wrap the query in an application-level TTL cache using `threading.Lock` and reset the cache globals cleanly in `conftest.py` before each test.
