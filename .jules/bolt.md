## 2024-06-07 - In-Memory TTL Cache with Double-Checked Locking
**Learning:** The synchronous Supabase Python client can become a bottleneck on heavily accessed read-only routes like `/leaderboard`. Adding an in-memory TTL cache using a standard Python dictionary and `threading.Lock()` mitigates this, but requires the "double-checked locking" pattern to avoid cache stampedes upon expiration (checking validity, acquiring the lock, then checking again).
**Action:** When implementing thread-safe caches, minimize lock duration by avoiding expensive operations (like `render_template()`) inside the lock block, and never use `return <expr>` directly inside the `with lock:` block because Python evaluates the expression before releasing the lock. Also, handle `None` fallbacks safely if the initial fetch fails.
