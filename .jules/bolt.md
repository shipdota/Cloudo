## 2024-05-20 - Thread-Safe TTL Caching and Concurrent Supabase Queries in Flask
**Learning:** In Flask apps utilizing a synchronous Supabase client, read-heavy global endpoints (like a leaderboard) can be optimized using a standard in-memory TTL dictionary and `threading.Lock()`. Furthermore, utilizing the double-checked locking pattern effectively avoids cache stampedes on expiration. For sequential database calls that do not rely on each other (like user profiles and scores), `concurrent.futures.ThreadPoolExecutor` safely leverages the underlying connection pool to run queries concurrently. However, because Flask's `session` object is bound to the request thread, values like `user_id` must be extracted prior to passing them to the worker threads to avoid context errors.
**Action:** Apply the double-checked locking pattern when implementing custom TTL caches, and extract thread-local variables before using `ThreadPoolExecutor` to parallelize independent I/O tasks.
