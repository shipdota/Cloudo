## 2024-05-24 - Thread-safe In-Memory TTL Caching
**Learning:** When implementing thread-safe, in-memory TTL caches in Flask without external dependencies like `cachetools`, the double-checked locking pattern is essential to prevent cache stampedes upon expiration. Furthermore, `time.time()` must be recalculated inside the lock to avoid race conditions caused by using stale values, and expensive operations like `render_template` must remain outside the lock block to minimize lock contention. Finally, never return directly from inside a `with` block holding a lock if the expression being returned is computationally expensive, as Python evaluates the expression before releasing the lock.
**Action:** Always apply the double-checked locking pattern for in-memory caches, recalculate timestamps inside the lock, and ensure expensive rendering or function calls are executed outside the lock.
