## 2024-06-08 - Optimize /leaderboard endpoint with in-memory cache
**Learning:** When implementing thread-safe caching with `threading.Lock`, it's critical to minimize the lock duration by only reading/writing the cache dictionary inside the lock block. Ensure expensive operations like `render_template()` or database queries are executed properly. Furthermore, because Python evaluates `return <expression>` *before* releasing the lock in a `with` block, returning an expensive function call directly from within the lock extends the lock time unnecessarily. Double-checked locking helps prevent cache stampedes upon expiration.
**Action:** Always store the result of expensive/locking operations in a variable, exit the `with` block, and then return or process it further, ensuring `render_template()` is outside the lock. Use the double-checked locking pattern correctly when checking cache expiration to avoid race conditions.
