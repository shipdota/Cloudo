## 2024-05-26 - Double-Checked Locking for In-Memory TTL Cache
**Learning:** When implementing thread-safe in-memory caching for expensive operations like `/leaderboard` queries in a Flask app, simply using a lock can block the main thread and degrade performance, especially if expensive operations like `render_template` are mistakenly kept inside the lock scope. However, failing to lock or verify the expiration correctly during cache refresh can lead to cache stampedes.
**Action:** Always use the double-checked locking pattern for in-memory TTL caches: 1) Check expiration outside the lock (fast path). 2) If expired, acquire lock. 3) Recalculate time and check expiration *again* inside the lock (slow path). 4) Fetch data and update cache. 5) Keep expensive rendering functions outside the lock to minimize lock duration.
