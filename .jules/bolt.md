## 2024-06-19 - Thread-safe Double Checked Locking for TTL Caches
**Learning:** When adding an in-memory TTL cache using standard library primitives (`time`, `threading.Lock`) to optimize endpoints like `/leaderboard` instead of introducing third-party dependencies, a naïve implementation might suffer from cache stampedes on expiration (multiple threads querying simultaneously). Furthermore, recalculating `time.time()` inside the lock is critical; otherwise, threads waiting on the lock might use stale time values that wrongly trigger sequential duplicate cache updates despite double checking.
**Action:** Always employ the double-checked locking pattern for in-memory TTL caches: fast-path check, lock acquisition, recalculate time, slow-path check, update cache. Ensure exceptions in the cache update fallback to safe data types (e.g., empty lists) rather than causing crashes.
