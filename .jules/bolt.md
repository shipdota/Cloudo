## 2024-05-25 - Supabase create_client Thread-Safety & Caching Anti-Pattern
**Learning:** In the backend `app/game.py`, creating authenticated user clients via `create_client` using session tokens is required for RLS (Row Level Security). However, Supabase `Client` maintains an HTTP connection pool via `httpx.Client`. Caching these instances via `functools.lru_cache` without properly evicting and calling `.close()` results in unclosed sockets, connection exhaustion, and memory leaks. Conversely, modifying a single global Supabase client with `.postgrest.auth(token)` is not thread-safe and can lead to authentication clobbering across concurrent requests.
**Action:** When optimizing backend Supabase requests, avoid global client mutation for auth, and NEVER blindly cache `create_client` instances for users without a proper cache eviction strategy that closes the underlying `httpx.Client` connections. For frontend optimizations, rely on DOM object pooling and layout caching.
